## 2. What Phase 4 changed

Spec: `docs/superpowers/specs/2026-07-24-phase4-project-creation-handoff.md` (expanded in place
from a handoff-only scope; it now covers all five slices).

### Scene/shot list — editable and synced

- **`concepts` ARE scenes.** They get real scene names; the default is `Scene N`, not `Concept N`.
- Shots are identified by **label** (`1A`, `1B`, `2A`) via `shotLabel(conceptIndex, shotIndex)`.
  The flat `Shot 3` default name is gone — a shot's `name` is now the human beat, and may be `''`.
- `relabel()` in `store.js` re-derives every label after any add / remove / reorder. Idempotent,
  matching the backfill in `load()`.
- New store functions: `renameConcept`, `removeConcept`, `removeShot`, `reorderConcept`,
  `reorderShot`, `updateShotFields`, `lockShotPrompt`, `unlockShotPrompt`.
- Removing the active scene or shot moves `doc.ui.activeConceptId` / `activeShotId` to a
  neighbour instead of leaving a dangling pointer.

**Both surfaces edit the same objects through `Store`** — that is the load-bearing invariant.
`projects.html` `renderOverview` is now a single-column scene list (not the old 2-up card grid)
with expandable shot rows; `promptbuilder.html` got a scene picker, a label-led shot picker,
and reorder/delete beside add/rename. Verified by editing in each and seeing it in the other.

The four descriptive fields — `subject`, `action`, `environment`, `cameraIntent` — live **in
`shot.builder`**, the same object the builder already persisted. One data model, nothing to
drift. `updateShotFields` whitelists exactly those four keys so the project view cannot write
composition state.

### Locked prompts

`shot.locked = { prompt, video, stillModel, videoModel, at }` is a **snapshot** of what
`compilePrompt` / `compileVideo` already returned. Locking never re-composes anything. The lock
card is on the builder's Review step; the project page shows each shot's locked prompt with an
unlock control. Editing fields afterwards does not rewrite the snapshot (tested).

### Breakdown view

`renderBreakdown` in `projects.html`. Per-scene table mapping each shot to the assets it calls
for, from the existing attached-reference plumbing (`charRefIds`, `locRefId`, `propRefIds`,
`styleRefId`) against the project's typed reference assets.

⚠️ **Unconfirmed product decision:** characters and location are treated as **required** for
every shot; props and style look as optional. So an insert or prop-only shot (e.g.
`1B · Hand on the door handle`) shows a red **MISSING** for characters permanently. Nobody
signed off on that rule — it was invented during implementation. Change the `required` flags in
the `SLOTS` array, or add a per-shot "n/a" toggle.

### Model set

Stills: **GPT Image, Nano Banana Pro, Seedream**. Video: **Kling, Cinema Studio, Seedance**.
Sora, Runway Gen-4, FLUX.2 and Midjourney v7 removed from `stillProfiles()`/`videoProfiles()`,
the builder chip lists, `multishot.html`'s model map, the `aisetup.html` select, and
`promptcompile.js`'s `STILL_LEADS` / `VIDEO_CAPS`.

**Two traps here — read before touching the model list:**

1. **"Cinema Studio" is a LABEL. The id is still `higgsfield`.** That string is the de-facto
   *surface* key read by `usesAtTags()` (`promptbuilder.html`), `videoRefMode()`
   (`promptcompile.js` `VIDEO_CAPS`) and the v0.3.92 motion-realism tail — and it is persisted as
   `builder.videoModel` on every saved shot. Renaming the id breaks @-handle tags, the
   reference-array mode and the motion tail, and orphans existing data. The two-axis `surface`
   field from `docs/superpowers/specs/2026-07-17-model-surface-two-axis.md` is **still
   unimplemented**; there is no `surface` field anywhere in `src/`, despite later specs assuming
   one.
2. **The step-5 model chips resolve by ARRAY INDEX**, not by label (`profs[i]`). The chip list
   order MUST match the profiles array order. A first draft of this work listed Cinema Studio
   second against a profiles order of kling/seedance/higgsfield, which made clicking
   "Cinema Studio" select Seedance. Both call sites now carry an ORDER MUST MATCH comment.

Shots saved with a retired id are coerced by `normalizeModel()` on load, so old data never
reaches `videoRefMode()` with a key it doesn't know.

### Handoff — Claude authors zero prompts

`generatorGuide()` in `newproject.html` is **deleted**. The instruction now forbids generation
prompts outright and asks for setup only: scenes, short label-led shot names
(`"1A · Man enters the bodega"`), the four fields as data, a per-shot breakdown, a to-do list of
what the *user* must produce, and locked descriptions that are **facts only**. Human docs export
as PDF, not markdown.

`scaffoldFromPlan` reads a `scenes` key (still accepts legacy `concepts`/`tasks`), carries the
four fields onto `shot.builder`, carries `shot.breakdown`, and turns `descriptions` into typed
reference assets with an empty prompt and no image so the breakdown flags them as
still-to-create. **Order matters in that function:** descriptions are imported first, because
`addReference` saves and the doc is re-read afterwards — doing it later silently dropped the
in-memory todos.

## 3. Phantom features removed (`56348b9`)

From the audit at `~/Downloads/Studio-S-phantom-features-audit.md`, after re-verifying each claim:

- `projects.html` `#np-modal` + its `closeNewProject` / `npPickFolder` / `createProject`
  handlers. `openNewProject` redirects to `index.html?new=1` and nothing ever set the modal
  visible. The page's reactive `state` existed only for the modal's folder path and is now `{}`.
- `store.js` settings `onboarded`, `defaultModel`, `defaultStillsModel`, plus the two AI-setup
  controls that wrote them. Sofia's call: delete, not wire, since there is no generation
  connector yet. **`defaultVideoModel` stays** — the builder honours it in `seedFromActive`.
  Already-saved values survive via the non-destructive settings merge in `load()`.
- `palmier.html` kickoff-prompt block — four chips with no handlers over a textarea of hardcoded
  copy describing a project that doesn't exist. Palmier's kickoff gets built properly later.
- `palmier.html` "Send history" — fabricated records ("3 sends", "Today, 2:14 pm · 2 concepts",
  "Yesterday", "Mon"). Entirely static markup for sends that never happened.

**Kept, correcting the audit:**

- `ui.activeClientId` / `activeDeliverableId` are **not** write-only — `setActive` writes them and
  `tests/store-v2.test.cjs:25` asserts them. Agency-spine scaffolding, same category as
  `clients`/`deliverables`, which the audit itself says to leave alone.
- Palmier's "Models in Palmier timeline" and "Export from Palmier" are descriptive info, not dead
  controls, and the MCP endpoint literal matches the config snippet lower on the same page.
- `Store.saveOk` / `deleteAsset` / `shotLabel` / `defaultBrand` / `defaultSpecs` stay exported.
  Note `shotLabel` is now load-bearing internally even though nothing calls `Store.shotLabel`.
